## 二、四阶段执行计划

### 阶段 0（1～2 天）基线

```bash
cd "/Users/mac/Desktop/工作 /软件/茅台抢单软件"
.venv/bin/python scripts/protocol_verify.py
.venv/bin/python scripts/collect_baseline.py
```

Web：**系统设置** → **应用中签优化模板** → 确认 `reserve_execution.mode=mobile`

填写 [`templates/申购日数据采集.csv`](./templates/申购日数据采集.csv) 基线行（账号数、出口组、业务员人数）。

### 阶段 1（1 周）9～30 号试点

| 时间 | 动作 |
|------|------|
| 平日 | 管理 App 本机 4G 登录待登号 |
| 8:50 | 查看 `data/protocol_health.log` 或跑 `daily_health_check.sh` |
| 9:00 | App「等到 9 点 · 本机预约」 |
| 18:03+ | Web/App 同步中签；待付 PushPlus |
| 周末 | Web → 合同验收 预览报告 |

### 阶段 2（2～3 周）50～100 号 × 3 申购日

```bash
.venv/bin/python scripts/contract_acceptance_report.py --days 30 --target-accounts 100
```

与甲方确认：**只验预约提交率 ≥80%**，不含 20% 中签率。

### 阶段 3（持续）按数据调优

- 仪表盘失败 Top 原因 → 调代理 / 登录 / 选店  
- 中签分析 → 调整 `min_competition` / 绑店  
- App 升级后重跑 `protocol_verify.py`

## 五、失败原因 → 对策

| 原因 | 对策 |
|------|------|
| 429_频控 | 模式 B；勿 Web 批量发码；加出口 |
| Token失效 | App 本机重登；看 8:55 推送 |
| sessionId异常 | 仅在 9:00–10:00 正式预约 |
| 4820_版本过低 | `protocol_verify`；更新 MT-APP-Version |
| 无库存/选店失败 | 试跑推荐；`shop_fallback` |
