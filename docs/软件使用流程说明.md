# 茅台抢单管理软件 — 使用流程说明

**版本**：v1.2 · 2026-06-11  
**业务目标（与客户对齐）**：**直购成交数** — 20:00 平价飞天 **1499 元 H5 下单成功**，不是 9:00 申购 **中签** 为主 KPI。
**适用对象**：管理员（老板/运营）、全球业务员（现场用手机）  
**推荐方式**：**模式 B** — 手机 4G 直连 i茅台，数据汇总到云服务器

## 一、系统是干什么的

本软件帮助公司 **批量管理 i茅台 客户手机号**，在 **20:00 平价飞天直购** 时段自动/半自动 **H5 抢购下单**，并统计 **直购成交**；同时保留 **9:00 申购抽签**、中签同步等能力（**辅线**，非主 KPI）。

| 重要概念 | 说明 |
|----------|------|
| **直购成交**（主 KPI） | 20:00 起 H5 **下单成功**（`priorityRecordId` 等），1499 官方价；客户在 **官方 i茅台 App** 内付款 |
| **预约 / 中签**（辅线） | 9:00 提交申购 → 官方抽签 → 中签后付款；**中签率不由软件保证** |

## 一点五、先搞懂：官方 i茅台「抢酒」是什么（2026）

网上说的 i茅台 **「抢酒」**，通常不是线下哄抢，而是：在 **i茅台 App** 里，以 **官方指导价**（如飞天 **1499 元**）购买热门茅台酒。人多货少，大家像抢限量球鞋一样 **拼手速、拼网速**——成功下单才算「抢到」。

这与本软件的 **「批量预约管理」** 有关但不完全相同，务必分清下面几种场次：

| 场次类型 | 官方时间 | 怎么玩 | 成功 = 什么 | 本软件 | **业务权重** |
|----------|----------|--------|-------------|--------|----------------|
| **平价飞天直购**（客户要的「抢酒」） | **20:00 起**（20:05–20:50 补货） | 拼手速 H5 下单 | **直购成交** | ✅ App「等到 20 点 · 本机直购」（≥1.8.0） | **主 KPI** |
| **申购抽签**（传统） | 约 **9:00–10:00** | 预约 → 抽签 | **中签**（随机） | ✅ App「等到 9 点 · 本机预约」 | 可选 / 养号 |
| **小茅好运专场** | 每月 29 日 **20:05** | 扣小茅运 | 专场规则 | ✅ 服务器 `lucky_special` | 可选 |
| **周末欢乐购** | 周日 **15:05** | 周末专场 | 视商品 | ✅ `weekend_happy` | 可选 |

**关于「晚上 9 点」**：截至 2026 年公开报道，i茅台 已将部分茅台酒 **开售时间从早 9 点调整为晚 8 点（20:00）**，**没有独立的 21:00 场次**。若听到「晚上抢茅台」，多半指 **20:00 直购场**，不是 21:00。

**本软件 ≠ 外挂**：不能代替官方 App **付款**；**不保证**每号都能直购成功（仍秒空、有风控）；合规用途是 **批量管理 + 提高直购下单成功率**。

**日常主流程（直购成交导向）**：

1. 白天：App **本机发码登录** 客户号（4G）  
2. **19:5x**：**直购试跑** 确认 Shield / 活动 ID  
3. **20:00**：App **「等到 20 点 · 本机直购」**（关 Wi-Fi、4G）→ 主抢 + 补货波次  
4. Web **预约记录** 看各号成功/失败（H5 直购也会写入记录）  
5. 成交号 → 客户在 **官方 i茅台 App** 付款  

9:00 预约、18:03 中签同步：**按需开启**，不作为主 KPI 考核。

## 二、两类账号（必分清）

```text
┌─────────────────────────────────────────────────────────┐
│  A. 管理账号（owner / client）                           │
│     → 登录「管理 App」或「Web 网页」                      │
│     → 管公司、看数据、配商品，不是 i茅台 手机号           │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│  B. i茅台 客户账号（11 位手机号）                         │
│     → 在管理 App「账号」页做 本机发码 + 本机登录          │
│     → Token 同步到公司服务器，供 **20 点直购 / 可选预约** 使用           │
│     → 不是业务员自己的私人 i茅台号（除非业务如此约定）    │
└─────────────────────────────────────────────────────────┘
```

| 对比 | 管理账号 | i茅台 客户账号 |
|------|----------|----------------|
| 登录入口 | App 首页 / Web 登录页 | App「账号」页 |
| 登录方式 | 用户名 + 密码 | 手机号 + **短信验证码** |
| 数量 | 少数（老板、业务员共用或分角色） | 很多（如 9、50、1000 个） |
| 存在位置 | 服务器管理员表 | 服务器「账号管理」数据库 |

## 三、整体架构（模式 B）

```text
                    ┌──────────────────────┐
                    │  云服务器             │
                    │  Web + API + 数据库   │
                    │  （存 Token、记录）   │
                    └──────────┬───────────┘
                               │ HTTPS（仅管理数据）
         ┌─────────────────────┼─────────────────────┐
         │                     │                     │
         ▼                     ▼                     ▼
  [老板电脑 Web]      [业务员手机·管理 App]    [定时任务]
  导入账号/看板        4G 直连 i茅台            Shield 签名 / 养护
         │                     │
         │                     ├── 发码 / 登录 ──► i茅台
         │                     └── 20:00 H5 直购 ──► i茅台（主）
         │
         ▼
  [客户手机] 收短信验证码；中签后在「官方 i茅台 App」付款、签到
```

**要点**：发码、登录、预约 **不走服务器公网 IP**（避免 429），只把 **结果和 Token** 同步到服务器。

## 五、首次上线流程（管理员）

### 5.1 服务器与 Web（一次性）

1. 部署 API + Web（见 [服务器选购与部署指南.md](./服务器选购与部署指南.md)）。
2. 配置 `config.yaml` / `deploy/.env`（`secret_key`、管理员密码等）。
3. 浏览器打开 Web，用 **owner** 登录。
4. **商品管理** → 飞天设为 **h5_rush** + 填写 **item_priority_act_id**（见 [Reqable 抓包](./方案二-Reqable仅抓i茅台.md) 或 `H5_ACT_ID`）。
5. 确认 `config.yaml` 含 **rush_schedule**（默认 20:00 + 补货波次）。
6. （可选）9 点抽签商品保持 `purchase_mode: reserve`。

### 5.2 下发业务员 App（一次性）

1. 编译或发布 APK（版本 ≥ **1.8.0**），上传到服务器 `downloads/`。
2. 把安装地址发给业务员，例如：  
   `http://你的服务器/downloads/maotai-reserve.apk`
3. 告知业务员：
   - 服务器地址（须以 `/api/v1/` 结尾），例如：  
     `http://你的服务器/api/v1/`（**用 http，不要用 https**，除非已开放 443）
   - 管理账号密码（**owner** 或分配的 **client**）
   - **登录管理 App 可开 Wi-Fi**；**发码 / 20 点直购 i茅台 须关 Wi-Fi 用 4G**

### 5.3 导入客户手机号（批量）

**Web → 账号管理 → 导入 CSV / Excel**

- 最少一列：**手机号**（11 位）。
- 可选列：省份、城市、出口组、选店策略、备注等。  
- 模板见项目 `账号导入模板.xlsx` 或 `docs/accounts-import.example.csv`。

导入后状态为 **「未登录」**，需业务员在 App 完成下文第六节。

## 六、业务员日常使用流程（核心）

> **网络要求（2026-06 实测）**  
> - **登录管理 App / 同步数据**：**开 Wi-Fi 即可**（部分运营商 4G 直连服务器 IP 会失败）  
> - **本机发码、20 点直购 i茅台**：**关闭 Wi-Fi，仅用 4G/5G**

### 6.1 第一次打开 App

| 步骤 | 操作 |
|------|------|
| 1 | 安装管理 App（见 5.2，当前推荐 ≥ **1.8.0**） |
| 2 | **开 Wi-Fi**，填写 **http://服务器/api/v1/** + **管理账号密码**（client / owner） |
| 3 | 登录成功后进入 **首页** |

此步登录的是 **管理账号**，不是客户 i茅台 号。

### 6.2 登记并登录一个客户 i茅台 号

在 App **「账号」** 页：

| 步骤 | 按钮/操作 | 说明 |
|------|-----------|------|
| ① | **新增账号**（若 Web 已导入可跳过） | 填客户手机号、省份城市、地址、选店策略 |
| ② | **本机发码** | 手机直连 i茅台，向该号发送短信验证码 |
| ③ | 在弹窗输入 **短信验证码** | 验证码发到 **客户手机**（或该号绑定 SIM） |
| ④ | **本机登录** | 手机直连 i茅台 完成登录 |
| ⑤ | 自动完成 | **Token 同步到公司服务器**，列表显示 **「已登录」** |

**「绑定」含义**：不是绑业务员私人号，而是 **把该客户手机号的 i茅台 登录态交给公司系统保管**。

可选：点账号进入 **编辑**，补全收货人、详细地址、固定门店、`max_inventory` / `min_competition` 等策略。

### 6.3 重复 6.2，直到负责的客户号都「已登录」

- 建议 **每台手机、每个 4G 出口** 负责约 **20 个号**（降低风控）。
- 发码间隔不要太密，收到码再登，避免 429。

**进度查看**：Web/App **首页** 或 **批量登录** 页可看「已登 / 待登」数量。

### 6.4 每天 H5 直购（约 20:00 · **主 KPI：直购成交**）

> **1499 平价飞天直购** = 客户说的「抢酒」。须 **App ≥ 1.8.0**。

**前置（管理员 Web）**：

1. **商品管理** → 飞天：`purchase_mode` = **h5_rush**，`item_priority_act_id` = 活动 ID（如 **86298**）  
2. `config.yaml` 含 **rush_schedule**（默认 20:00 + 20:05–20:50 补货）

**业务员 App（每天 · 必做）**：

| 按钮 | 何时用 |
|------|--------|
| **直购试跑** | **19:50 前** 检查 Shield / 活动 ID / Token |
| **等到 20 点 · 本机直购** | **正式日必点**；20:00 主抢 + 补货波次 |
| **立即本机直购** | 补跑、测试 |

**网络**：关 Wi-Fi，仅用 **4G/5G**。

**怎么看成交**：App 日志出现「抢购成功 priorityRecordId=…」；Web **预约记录** 有成功条目；仪表盘看成功数。**成交后** 客户在官方 i茅台 App 付款（本软件不代付）。

### 6.4b 每天申购（约 9:00 · 抽签 · **可选**）

> **非主 KPI**。仅当客户仍要兼顾抽签或养号习惯时使用。

| 按钮 | 何时用 |
|------|--------|
| **等到 9 点 · 本机预约** | 需要抽签资格时 |
| **本机试跑** | 检查 Token / 选店 |

结果回写 **预约记录**；**18:03** 后可同步 **中签**（与直购成交分开统计）。

### 6.5 中签与付款（约 18:00 后 · **抽签辅线**）

仅当你仍做 **9:00 预约** 时需要：

| 步骤 | 操作 |
|------|------|
| 1 | App 或 Web **「中签与付款」** → **同步中签结果** |
| 2 | 查看 **待付款** 列表 |
| 3 | 通知客户在 **官方 i茅台 App** 内 **24 小时内付款** |
| 4 | 财务确认后可在系统 **标记已付** |

本软件 **不能代付**，只能提醒与记录。

### 6.6 养号（提高账号质量，建议每天）

| 事项 | 谁来做 | 说明 |
|------|--------|------|
| 连续每日预约 | 系统自动 + 业务员 9 点预约 | 软件侧 |
| 小茅运 / 旅行 | 服务器定时 + App「小茅运旅行」 | 软件辅助 |
| **签到 / 答题** | **客户或业务员在官方 i茅台 App** | 必须人工，软件仅提醒 |
| 低分账号养护 | 服务器每天 **07:30** 自动；可手动点「低分养护」 | Token 检查 + 旅行 + 推送提醒 |

## 八、服务器自动任务（无需业务员点击）

启用 `MT_SCHEDULER_ENABLED=true` 且 API 服务运行中时：

| 任务 ID | 默认时间 | 作用 |
|---------|----------|------|
| `token_check` | 07:00 | 检查 Token 是否失效，异常 PushPlus 提醒 |
| `nurture_maintenance` | 07:30 | 养号分 &lt; 40：旅行、实验签到、提醒 App 签到 |
| `daily_reserve` | 约 8:54 起 | 服务器端预约（**模式 B 下请用 App 本机预约**，此项可能 429） |
| `lottery_sync` | 18:03 | 同步中签、待付款推送 |
| `lottery_sync_retry_*` | 18:13 / 18:23 | 中签同步失败时自动重试 |
| `protocol_verify` | 08:50 | 协议版本/SALT/AES 巡检 |
| `pre_reserve_token` | 08:55 | 9 点前 Token 复检 |
| `travel_batch` | 一三五 08:30 | 小茅运旅行（模板开启后） |
| `weekend_happy` | 周日 15:05 | 周末欢乐购（可选） |
| `lucky_special` | 每月 29 日 20:05 | 小茅好运专场（**不是** 20:00 平价飞天直购） |
| `proxy_probe` | 06:30 | 代理出口信誉探测（V+2） |

**V+1/V+2**：详见 [V+1-V+2运维升级说明.md](./V+1-V+2运维升级说明.md)（出口健康看板、手机分片、混合路由）。

**模式 B 建议**：每日申购以 **业务员 App「等到 9 点 · 本机预约」** 为主；服务器 `daily_reserve` 仅在已有可用代理、非 429 时作补充。

在 **Web 仪表盘** 底部可查看各任务 **下次执行时间**。

## 十、常见问题

### Q1：业务员下载的是官方 i茅台 吗？

不是。下载的是 **「茅台管理 App」**（公司定制）。官方 i茅台 仍用于客户 **付款、签到**。

### Q2：Token 同步到服务器后，客户还能用自己手机登 i茅台 吗？

可以。但若客户在官方 App **重新登录**，可能导致服务器里 Token **失效**，需在管理 App **重新本机发码登录**。

### Q3：Web 上点「发码」失败怎么办？

说明服务器 IP 被限流（429）。**不要用 Web 发码**，改让业务员在 App 用 **本机发码 / 本机登录**。

### Q4：一台手机能登多少个号？

**方案 B（多卡少机）**：瓶颈是 **电话卡 + 4G 出口**，不是手机台数。

| 阶段 | 做法 |
|------|------|
| 登录 | 插卡 A → App **本机发码/登录** → 换卡 B 重复（每号独立 `device_id` 已存服务器） |
| 预约 | 已登录号可在 **同一 4G** 上由 App 批量提交（建议单出口 **≤20 号**） |

3 台手机 + 100 张卡可行：登录阶段轮换 SIM，9 点可由少数手机分担预约。换卡后若 Token 失效，Web **重置指纹** 后 App 重新本机登录。

1000 号约需 **50 路 4G 出口**（或 50 组轮换），不是必须 50 台物理手机。

### Q4b：怎么提高 **直购成交数**？（主 KPI · App ≥ 1.8.3 全极限）

1. 商品 **h5_rush** + **活动 ID 每日更新**  
2. **19:50 直购试跑** → **20:00「等到 20 点 · 本机直购」**（前台服务保活，跑完全部波次）  
3. **关 Wi-Fi、4G**；单出口 **≤20 号**  
4. 全极限（已内置）：**12 签齐射**、**6 账号并行**、**每号 48 连打**、**T-3s 预签名**、**20:00 微波次 + 补货波次**、**H5 预热 + 毫秒卡点**  
5. 仍 **不保证** 每号成交，但已接近单机软件极限；1000 号需 **50 路 4G 同时开抢**

### Q4c：还要做 9 点预约吗？

**主 KPI 是直购成交时可不做。** 若客户仍要抽签，保留 9 点预约；与中签分析分开考核。

### Q5：怎么知道今天 **直购** 有没有成功？

- App 预约后看日志/提示  
- Web **预约记录** 看成功/失败  
- 仪表盘看 **提交成功率**

- App 直购日志「抢购成功 priorityRecordId=…」  
- Web **预约记录** 成功条目（H5 与预约共用表）  
- 仪表盘 **提交成功率** / 成功条数  

### Q6：直购成交能保证吗？

不能。仍 **秒空、竞争激烈**；软件提高的是 **多账号、多波次、连打** 的 **下单成功概率**，不是 100% 买到。

### Q7：晚上 9 点要不要抢？

**没有 21:00 场。** 平价飞天是 **20:00 直购**（主 KPI），不是 9 点抽签，也不是 21 点。
