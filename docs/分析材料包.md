## 1. 系统架构（模式 B）

### 1.1 设计原则

**Wi-Fi 连管理，蜂窝打 i茅台** — 从根源解决 IP 隔离：管理服务器走 Wi-Fi，i茅台 H5 直购仅走蜂窝，禁止静默 fallback 到 Wi-Fi（App ≥ 1.9.4）。

```text
业务员手机（Wi-Fi + 4G 同时开启，App 自动分流）
  │
  ├── MANAGEMENT 通道（OkHttp NetworkLane.MANAGEMENT）
  │     └── 139.155.134.97/api/v1/
  │           ping / rush-bundle / sign-rush-batch / report-reserve
  │
  └── IMAOTAI 通道（OkHttp NetworkLane.IMAOTAI）
        └── h5.moutai519.com.cn（rushPurchase POST，仅蜂窝）

云服务器
  ├── FastAPI + SQLite（admin.db）
  ├── Shield WASM 签名（不向 i茅台 直购，mobile 模式）
  ├── Vue Web 管理端
  └── APK 分发：/downloads/maotai-reserve.apk
```

### 1.2 关键约束

| 项 | 值 |
|----|-----|
| 单手机账号上限 | ≤20（`MAX_ACCOUNTS_PER_PHONE`） |
| 主 KPI 商品 | item_code `10941`，act_id `86298`（20:00 平价飞天 H5 直购） |
| 登录通道 | 20 点直购号须 `login_channel=phone_*`（App 本机 4G 发码登录） |
| 分片 | `worker_shard=phone-01`（可扩展多手机） |
| 执行模式 | `rush.execution_mode=mobile`（服务器仅签名，手机 POST） |

### 1.3 统一网络口径（App 1.9.4+）

> Wi-Fi 与移动数据请同时开启，App 自动分流，无需手动切换。  
> 管理服务器 → Wi-Fi 优先；i茅台 → 仅蜂窝，失败不会自动切 Wi-Fi。  
> 关 VPN、关个人热点。开战前须「检测网络」：管理服务器 + i茅台 蜂窝均通。

#### 3.1.1 OkHttpFactory 关键结论

| 问题 | 实现 |
|------|------|
| 蜂窝 Network 来源 | `NetworkHolder.resolveCellular()` 优先，否则被动扫描 `allNetworks` |
| MANAGEMENT failover | Wi-Fi → 蜂窝（允许） |
| IMAOTAI failover | **仅蜂窝，禁止 Wi-Fi fallback**（1.9.4+） |
| 连接 reset 重试 | fast 模式 2 次 / normal 3 次；间隔 60ms×n 或 800ms×n |
| 默认超时 | connect 60s / read 120s（i茅台 fast 可配 12s） |
| Client 缓存 | `ConcurrentHashMap`，蜂窝变更后 `invalidateClients()` |

#### 3.1.2 NetworkHelper 门禁逻辑

**硬拦截（`rushBlockReason`）**：

1. VPN 已连接 → 提示关闭 VPN/加速器  
2. 个人热点已开 → 提示关闭热点  
3. 无 SIM → 提示插入 SIM 并开移动数据  

**「等到 20 点」门禁（`rushWaitGate`）**：

1. 上述硬拦截  
2. `serverReachable == false` → 管理服务器不可达  
3. `imaotaiReachable == false` → i茅台 蜂窝通道不通  
4. 未点「检测网络」（两项为 null）→ 阻断  
5. `readiness.ready == false` → 备战 checklist 未完成  
6. 双网皆无 → 阻断  

#### 3.1.3 NetworkHolder（OP-18）

```kotlin
// android-app/.../util/NetworkHolder.kt
val request = NetworkRequest.Builder()
    .addCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)
    .addTransportType(NetworkCapabilities.TRANSPORT_CELLULAR)
    .build()
cm.requestNetwork(request, cb)
```

调用时机：App 启动（`MaotaiApp.onCreate`）、检测网络、开抢前（`LocalRushRunner.run`）。

#### 3.1.4 LocalRushRunner 关键逻辑

| 项 | 实现 |
|----|------|
| 波次 | `target_time` + `wave_times`（config 默认 20:00:01～20:55:00 多波） |
| 时间校准 | `bundle.serverTsMs` → `ClockSync.updateFromServer()` → `waitUntil()` |
| 并行账号 | `Semaphore(parallel)`，`parallel_accounts` 默认 4，cap 8 |
| 批量签名 | `signRushBatch(count=sign_burst_size)`，默认 8～12 |
| 预签名（OP-22 部分） | 开战前 `preSignFirstBurst()`，首批 `parallel×2` 账号 |
| 429 | `stop_on_429=true` 时停止本波次；cooldown 默认 180s |
| 齐发 | `burst_parallel=true` 时同批签名请求并行 POST |
| 回写 | 结束后 `POST /mobile/report-reserve` |

## 8. 分析报告建议维度

材料到位后，建议按以下结构输出，每维标注风险等级（高/中/低）：

### 8.1 架构设计评估

- 技术选型：FastAPI + SQLite + Vue + Android Compose + Shield WASM  
- 分层：共享 `src/` 协议库 + backend 服务层 + Android Worker  
- 模式 B 网络分流设计合理性  

### 8.2 稳定性与风控

- 429/封号威胁与 `stop_on_429`、egress_health 效果  
- 蜂窝在 Wi-Fi 下可用性（requestNetwork + 实战验证）  
- IMAOTAI 禁止 Wi-Fi fallback 的安全性  
- 门禁 false negative（全绿但 0 请求）历史案例  

### 8.3 安全审计

- Token 加密存储（Fernet + secret_key）  
- 生产 HTTP 传输风险（P0）  
- 接口 JWT 鉴权  
- APK 逆向保护（ProGuard 级别）  

### 8.4 性能与容量

- 单手机 ≤20 账号上限  
- Shield 批量签名吞吐（ThreadPool max 8）  
- SQLite 并发（单写者模型）  

### 8.5 可运维性

- 部署：`deploy/maotai-api.service` + nginx  
- 监控：journalctl / reserve_records / rush-readiness API  
- SOP：`docs/业务员手机操作指南.md`、`docs/20点直购失败决策树.md`  

### 8.6 可交付性

- 合同对照：`docs/合同功能验收说明.md`  
- 文档完整性：43 篇 docs/  
- 多环境：config.yaml + worker_shard 分片
