# 可交付部署方案（中心管理 + 本机热点抢酒）

**版本**：v1.0 · 2026-05-27  
**适用**：服务器 IP 已 429、无可用代理、先交付 9～50 号稳定跑通，再扩 1000 号。

---

## 一、交付架构（定稿）

```text
┌─────────────────────────────────────────┐
│  云服务器（只做管理，不打 i茅台）          │
│  Web 管理端 + API + 账号库 + 任务记录    │
│  ❌ 不在服务器点「执行预约」（会 429）    │
└──────────────────┬──────────────────────┘
                   │ HTTPS 拉凭证 / 写 Token
┌──────────────────▼──────────────────────┐
│  Mac 本机 Worker（连 4G 热点）            │
│  登录 / 预约 / H5 抢购 → 蜂窝 IP 出口 ✅   │
└─────────────────────────────────────────┘
```

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| 服务器 | 账号管理、商品、任务记录、定时编排 | 不向 i茅台 发预约/发码 |
| Mac + 热点 | 发码登录、试跑、9:00 抢酒 | — |

扩到 1000 号时：复制 **N 台本机 Worker**（或 N 台小云主机每台 20 号），结构不变。

## 三、第一期：今天部署（9 号试点）

### 步骤 1：服务器（10 分钟）

```bash
# 服务器上
cd /opt/maotai
git pull   # 或上传最新代码
.venv/bin/pip install -r backend/requirements.txt wasmtime curl_cffi
sudo systemctl restart maotai-api   # 或你的重启方式
```

确认 Web 能打开；**关闭**服务器定时任务里「直接在服务器跑全量预约」（或接受 429 仅作记录）。

### 步骤 2：Mac 准备（5 分钟）

```bash
cd "/Users/mac/Desktop/工作 /软件/茅台抢单软件"
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r backend/requirements.txt wasmtime curl_cffi

# 从服务器复制（secret_key 必须一致）
scp ubuntu@你的服务器:/opt/maotai/config.yaml ./config.yaml

cp worker.env.example worker.env
# 编辑 worker.env：SERVER_URL、OWNER_PASSWORD
chmod +x 启动本机登录.command 启动本机抢酒.command
```

### 步骤 3：登录（热点）

1. Mac **只连手机 4G 热点**，关 Wi-Fi  
2. 双击 **`启动本机登录.command`**  
3. Web → 账号管理 → 确认 9 号「已登」

### 步骤 4：试跑抢酒

1. 仍连热点  
2. 双击 **`启动本机抢酒.command`** → 选 **1 试跑**  
3. 日志应有 `🔍` 或选店/加密预览，无 Token 失效

### 步骤 5：正式 9:00 抢酒

1. 热点保持连接  
2. `启动本机抢酒.command` → 选 **3 等到 9 点再抢**  
3. 或提前一晚运行，脚本会等到 `config.yaml` 里 `schedule.target_time`

## 四、第二期：扩到 50 号（1 周内）

| 天 | 动作 |
|----|------|
| D1～D3 | 1 手机热点，每换 IP 登 20 号：`batch_local_login.py --from-id X --to-id Y` |
| D4 | Web 核对 50 号已登 |
| D5 | 本机 Worker 试跑 50 号 |
| D6+ | 每天 9:00 本机 Worker；或按 20 号/批轮换热点分 3 天抢 |

`config.yaml` 建议：

```yaml
account_stagger_seconds: 0.8
antidetect:
  enabled: true
  stable_fingerprint: true
  max_reserve_per_minute: 6
schedule:
  target_time: "09:00:00"
  prewarm_minutes: 5
  wave_times: ["09:05:00", "09:10:00", "09:15:00"]
proxy_pools: {}   # 热点方案留空
```

## 五、第三期：1000 号（可选，按资源选一条）

| 路径 | 条件 | 做法 |
|------|------|------|
| **A. 本机 Worker × N** | 10 人 + 10 手机热点 | 每人 `worker.env` 里写 `ACCOUNT_IDS=…`，9:00 各跑各的 |
| **B. 50 台云 Worker** | 预算够、机房 IP 实测通过 | 每台部署代码，`ACCOUNT_IDS` 绑 20 号，中心 Web 管理 |
| **C. 买 4G 代理** | 不想用人 | `proxy_pools` 50 组，可改回服务器执行（需代理实测无 645） |

**不推荐**：1000 号全挤 1 台服务器 IP；天启机房 IP。

## 七、故障处理

| 现象 | 处理 |
|------|------|
| 发码 429 | 换热点 / 换 IP；用本机登录，勿用 Web 发码 |
| 645 | 换出口，勿用天启 |
| Worker 拉凭证 0 个 | 先本机登录 |
| secret_key 错误 | Mac `config.yaml` 与服务器 `MT_SECRET_KEY` 一致 |
| H5 抢购失败 | `python scripts/test_h5_shield.py` |
| 试跑 OK、9 点失败 | 9 点前保持热点；检查 sessionId |
