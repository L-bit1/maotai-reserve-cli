# 合同功能验收说明

本文对照《软件开发服务合同》功能清单，说明系统实现范围与可验收指标。

## 功能对照

| 序号 | 合同要求 | 实现状态 | 说明 |
|------|----------|----------|------|
| 1 | 用户登录与入库 | ✅ | Web/批量登录、DB 存 Token；服务器发码 429 时用 **模式 B**（手机/App 本机登录） |
| 2 | 酒类管理 | ✅ | `商品管理` + `/api/v1/products` |
| 3 | 定时自动抢购 | ✅ | App「等到 9 点」+ 服务器定时；默认 `reserve_execution.mode=mobile` 避免 100 号服务器 429 |
| 4 | 数据查询 | ✅ | 账号、预约记录、中签、仪表盘 |
| 5 | 后台统一付款 | ⚠️ | 待付款汇总/导出/批量标记/PushPlus；**无法在后台代扣 i茅台 订单**（平台限制） |
| 6 | 门店选配与查询 | ✅ | 门店主数据 CRUD、批量绑店、库存排行与推荐 |
| 7 | KPI 单次抢购成功率 ≥20% | ❌ 不可控 | 中签为官方抽签；软件仅保障 **预约提交成功率** |

## §4.1 验收指标（软件可控部分）

合同原文「3 次×100 号，预约 ≥80%，命中 ≥20%」拆分为：

- **预约提交率 ≥80%**：软件可测、可优化（代理/4G、模式 B、9 点场次）
- **命中 ≥20%**：官方抽签结果，**不能作为软件交付验收硬性指标**

### 生成验收报告

**Web**：侧边栏 → **合同验收**

**CLI**：

```bash
python scripts/contract_acceptance_report.py --days 30 --target-accounts 100
```

报告写入 `data/contract_acceptance_report.json`。

## 推荐生产配置

**客户手机充足**（10~20 号/部 4G）：

```yaml
reserve_execution:
  mode: mobile
```

**客户手机不足**（仅服务器 + 代理，见 `docs/无手机大规模部署方案.md`）：

```yaml
reserve_execution:
  mode: server   # 或 hybrid
antidetect:
  auth_prefer_proxy: true
```

大规模账号：每 10–20 号一个独立出口，勿在服务器公网 IP 上集中发码/预约。

## 统一付款流程

1. **同步中签**（中签与付款页）
2. **导出待付款 Excel** → 运营按单在 i茅台 App 支付
3. **批量标记已付** → 后台状态与 App 对齐

## 模式 B 登录

服务器 IP 被 EdgeOne 429 时：

1. Web **批量登录** 页导出未登录号
2. 手机 4G 或本机脚本 `scripts/local_login_to_server.py` 完成登录
3. Token 写入服务器 DB，后续预约由 App/Worker 执行

详见 `docs/手机Worker模式B.md`、`docs/软件使用流程说明.md`。
