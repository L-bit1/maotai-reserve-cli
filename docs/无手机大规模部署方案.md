# 无手机大规模部署方案（客户手机不足时）

当甲方**没有足够手机**做模式 B 本机登录/预约时，合同功能仍可通过 **服务器 + 出口代理** 交付，不依赖 Android Worker。

## 与合同条款的对应

| 合同项 | 无手机实现方式 |
|--------|----------------|
| 登录入库 | 服务器 Web 批量发码（**每号独立代理**）或 CSV 导入已有 Token |
| 定时抢购 | `reserve_execution.mode=server` 或 `hybrid` + 9 点 `daily_reserve` |
| 门店选配 | 门店主数据 + 库存排行 + 绑店（已实现） |
| 数据查询 | Web 仪表盘 / 预约 / 中签（已实现） |
| 统一付款 | 待付款汇总、导出 Excel、批量标记（**无法在后台代扣 i茅台**） |
| §4.1 80% 提交率 | 依赖代理质量 + 账号规模；见 **合同验收** 页 |

## 推荐配置

```yaml
reserve_execution:
  mode: server   # 或 hybrid：仅配置了 proxy 的号走服务器

antidetect:
  auth_prefer_proxy: true
  login_vcode_interval: 120

proxy_pools:
  ip001: "http://user:pass@1.2.3.4:8080"
  # … 约 100 号需 5~10 个住宅/4G 静态出口，每出口 10~20 号

max_accounts_per_egress: 20
```

## 操作步骤

1. **导入账号**（Web → 账号管理 → CSV）
2. **配置代理池**（系统设置 → 代理池；或快代理/住宅 IP 供应商）
3. **分配出口组**：`assign_egress_groups` 或 Web「为账号分配出口组」
4. **检测代理发码**：设置页「检测全部代理」
5. **批量登录**：批量登录页发码（走各自代理，勿用服务器直连）
6. **定时预约**：确认 `mode=server`，申购日看预约记录提交率
7. **验收**：侧边栏 **合同验收** 生成报告

## 代理选型（实测结论）

| 类型 | 100 号可行性 | 说明 |
|------|-------------|------|
| 服务器公网 IP | ❌ | EdgeOne 429，仅适合管理 API |
| IDC 静态代理（快代理等） | ⚠️ | 偶发可用，同 IP 连发易 429 |
| 住宅/4G 静态（每 10~20 号 1 出口） | ✅ | 合同 80% 提交率的主路径 |
| 一机一号真手机 | ✅ | 成本高，客户手机不足时不采用 |

## 与开源脚本的关系

[ken-iMoutai-Script](https://github.com/AkenClub/ken-iMoutai-Script)、[campus-imaotai](https://github.com/oddfar/campus-imaotai) 等也是 **Token + 定时调 API**，差异在本项目多了 **Web 管理端、DB、分出口组、验收报告**。无手机场景下思路一致：**多账号 + 分 IP + cron 9 点**。

## 仍无法写入软件的部分（需合同附件说明）

- **后台代扣 i茅台 订单**：官方无开放 API
- **中签率 ≥20%**：官方抽签，只能统计不能保障
