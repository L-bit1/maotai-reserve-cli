## 三、后面还可能踩的坑

| 类别 | 坑 | 预防 |
|------|-----|------|
| IP | 假住宅（实为共享机房） | 采购前 `proxy_compare_test.py`；要求独享静态 |
| IP | 1 IP 绑超过 20 号 | `--per-group 20`；H5 可试 1:1 |
| IP | 代理未加服务器白名单 | 核对 91HTTP 等白名单 |
| 活动 | act_id 按日变更 | 每日抓包或 `fetch_h5_act_id.py` |
| 手机 | App 后台被杀 | 19:55 前台、关省电 |
| 手机 | 误开 Wi-Fi | 直购必须 4G |
| 账号 | 新号/养号不足 | 养号后再抢 |
| 支付 | 换设备付款被拦 | 原设备原号付 |
| 规模 | 1000 号靠手机 | 需 ~50 台，不现实 → 必须独享 IP |
| 竞争 | 1499 飞天 1 秒售罄 | 接受低成交率 |

## 四、自组 IP 池（独享住宅 1:20）行不行？

| 问题 | 答案 |
|------|------|
| 能接入本系统吗？ | **能**（proxy_pools + egress_group + 门禁已具备） |
| 能保证 1000 号都成交吗？ | **不能**（库存与竞争决定） |
| 比今晚 3 条共享代理好吗？ | **大概率能**（前提是真·独享静态住宅，1 IP ≤20 号） |
| 今晚 429 能否反证无效？ | **不能**（失败的是共享机房池，不是独享住宅模型） |

**验证顺序**：手机 1 台有 Web 记录 → 买 3～5 条独享 IP 试点 3 晚 → 再扩 50 条/1000 号。

| 代理类型 | 100～1000 号 | 你们实测 |
|----------|--------------|----------|
| 共享机房（91HTTP/KDL） | ❌ | 首包 429 |
| 独享住宅/4G 静态（1:20） | ✅ 文档主路径 | **未采购验证** |
| 手机 4G | ✅ | **待 1 台验证** |
