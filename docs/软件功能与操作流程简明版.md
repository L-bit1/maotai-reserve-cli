**版本**：v1.0 · 2026-06-11  
**适用对象**：老板/管理员、现场业务员  
**推荐模式**：模式 B（手机 4G 直连 i茅台，数据汇总云服务器）

**相关文档**：[软件使用流程说明.md](./软件使用流程说明.md) · [Web管理端使用说明.md](./Web管理端使用说明.md) · [手机Worker模式B.md](./手机Worker模式B.md) · [现状与路线评估.md](./现状与路线评估.md)

## 分工说明（重要）

| 角色 | 负责什么 | 用什么 |
|------|----------|--------|
| **业务员（现场）** | 用手机完成客户号的 **本机发码 + 本机登录**，把号登进系统 | Android **管理 App** |
| **老板 / 管理员** | 客户号登录完成后，**统一在 Web 端操作**：导入账号、配商品/活动 ID、看仪表盘、查直购记录、分片与规模管理 | **Web 管理后台** |

**原则**：现场只负责「把号登进去」；商品配置、数据统计、批量监控、活动 ID 维护等 **统一交给老板在 Web 端处理**，避免多人重复改配置。

## 一、软件是干什么的

这是一套 **批量管理 i茅台 客户手机号** 的系统，核心目标是：

> **20:00 平价飞天 1499 元 H5 直购成交数**（主 KPI）  
> 9:00 申购抽签、中签同步等是 **辅线**，不是主考核指标。

### 软件能做的

| 能力 | 说明 |
|------|------|
| 批量管理客户号 | 导入几百～1000 个手机号，统一看登录状态、养号分、成功/失败记录 |
| 本机发码登录 | 业务员手机 4G 直连 i茅台，帮客户号收验证码、登录，Token 同步到服务器 |
| **20:00 H5 直购**（主） | App 自动卡点、批量签名、多账号并行抢购平价飞天 |
| 9:00 申购预约（辅） | 可选，提交申购资格，等官方抽签 |
| 中签同步与待付款提醒 | 18:03 后同步中签结果，提醒客户在官方 App 付款 |
| 养号辅助 | 小茅运旅行、低分账号养护、Token 巡检、PushPlus 提醒 |
| Web 看板统计 | 登录进度、预约/直购记录、中签分析、商品与活动 ID 配置 |

### 软件不能做的

- 不能代替客户在官方 i茅台 App **付款**
- 不能保证每个号都买到（库存秒空、风控、竞争）
- 不是外挂，合规用途是 **批量管理 + 提高下单成功率**

## 二、先分清两类「账号」

```text
管理账号（owner / client）
  → 登录「管理 App」或「Web」
  → 管数据、配商品，不是客户手机号

i茅台 客户账号（11 位手机号）
  → 在管理 App「账号」页 本机发码 + 本机登录（业务员现场完成）
  → Token 存服务器，供 20 点直购 / 9 点预约使用
  → 登录完成后，老板在 Web 端统一查看与管理
```

| 对比 | 管理账号 | i茅台 客户账号 |
|------|----------|----------------|
| 谁登录 | 老板 / 业务员 | 业务员在 App 帮客户号登录 |
| 登录方式 | 用户名 + 密码 | 手机号 + 短信验证码 |
| 日常谁管 | 老板 Web 统一操作 | 老板 Web 看状态；业务员 App 执行直购 |

## 三、系统架构（一句话）

```text
云服务器（Web + API + 数据库）  ← 老板 Web 统一操作
        ↑ 仅同步管理数据 / Token / 记录
业务员手机「管理 App」
        ↓ 4G 直连 i茅台（发码、登录、20 点直购）
客户手机
        → 收短信验证码；成交/中签后在「官方 i茅台 App」付款
```

### 关键原则

- **登录管理 App / 老板 Web**：可以开 **Wi-Fi**
- **本机发码、20 点直购**：必须 **关 Wi-Fi，只用 4G/5G**
- 发码/抢购 **不走服务器公网 IP**，避免被 i茅台 限流（429）
- **客户号登录完成后，配置与监控统一由老板 Web 端负责**

## 四、操作流程

### 阶段 1：首次上线（老板 / 管理员，一次性）

#### 1. 部署服务器

Web + API 跑起来（当前示例：`http://139.155.134.97`）

#### 2. Web 登录（owner 账号）

浏览器打开管理后台，由 **老板** 完成后续配置。

#### 3. 商品配置（每天最重要 · 老板 Web 操作）

- 飞天商品：`purchase_mode` = **h5_rush**
- 填写当日 **item_priority_act_id**（活动 ID，过期必失败）
- 可从抓包或 Web 商品管理获取

#### 4. 批量导入客户号（老板 Web 操作）

Web → 账号管理 → 导入 CSV/Excel（至少一列手机号）

#### 5. 下发管理 App 给业务员

| 项目 | 内容 |
|------|------|
| 安装地址 | `http://139.155.134.97/downloads/maotai-reserve.apk` |
| 服务器地址 | `http://139.155.134.97/api/v1/` |
| 管理账号 | 如 `client` / `mt@2026`（业务员仅用于登录 App） |
| 版本建议 | ≥ **1.8.3** |

告知业务员：**你只负责把客户号登进去；商品、活动 ID、看板由老板 Web 统一管。**

---

### 阶段 2：业务员日常（现场）

#### ① 登录管理 App（每天开始）

| 步骤 | 操作 |
|------|------|
| 1 | **开 Wi-Fi**，打开管理 App |
| 2 | 填服务器地址 + 管理账号密码 |
| 3 | 进入首页，看今日概览（登录进度以老板 Web 为准） |

#### ② 帮客户号登录 i茅台（白天完成 · 业务员核心职责）

在 App **「账号」** 页，对每个客户号：

| 步骤 | 按钮 | 说明 |
|------|------|------|
| 1 | 新增账号（或老板 Web 已导入则跳过） | 填手机号、城市、选店策略 |
| 2 | **本机发码** | **关 Wi-Fi、4G**，向该号发验证码 |
| 3 | 输入短信验证码 | 验证码发到客户手机 |
| 4 | **本机登录** | 4G 直连 i茅台 完成登录 |
| 5 | 自动同步 | 列表显示 **「已登录」**，老板 Web 可看到 |

**建议**：单部手机 / 单路 4G 负责 **≤20 个号**，发码不要太密。

**登录完成后**：通知老板 Web 端已登多少号；**不要自行改商品或活动 ID**。

#### ③ 20:00 直购（主战场 · 每天必做）

**老板先确认**（Web）：商品已配 `h5_rush` + 当日活动 ID

**业务员操作**：

| 时间 | 按钮 | 说明 |
|------|------|------|
| **19:50 前** | **直购试跑** | 检查 Shield、活动 ID、Token 是否正常 |
| **19:55 左右** | 关 Wi-Fi，开 4G | 网络必须正确 |
| **20:00** | **等到 20 点 · 本机直购** | 前台保活，自动跑主抢 + 20:05–20:55 补货波次 |
| 补跑时 | **立即本机直购** | 测试或漏跑补救 |

**成功标志**：App 日志出现 `抢购成功 priorityRecordId=…`

**成交后**：通知客户在 **官方 i茅台 App** 内付款（本软件不代付）；老板 Web 查预约记录统计。

#### ④ 9:00 预约（可选 · 抽签辅线）

只有老板要求兼顾抽签时才做：

| 按钮 | 说明 |
|------|------|
| **等到 9 点 · 本机预约** | 正式申购 |
| **本机试跑** | 检查 Token / 选店 |

#### ⑤ 18:00 后中签处理（仅做了 9 点预约时）

- 老板 Web → **中签与付款** → **同步中签结果**（或由业务员 App 触发同步）
- 看 **待付款** 列表
- 通知客户在官方 App **24 小时内付款**
- 财务确认后可 **标记已付**

---

### 阶段 3：老板 Web 日常（统一操作）

| 时间 | 做什么 |
|------|------|
| 随时 | **账号管理**：导入新号、看养号分、启用/禁用、看业务员登录进度 |
| 随时 | **仪表盘**：已登录数、成功/失败统计 |
| **每天 20 点前** | **商品管理**：确认 **活动 ID 未过期** |
| 20 点后 | **预约记录**：看各号直购/预约成功失败，统计主 KPI |
| 18 点后（可选） | **中签分析**：仅在做 9 点抽签时需要 |
| 按需 | 分片配置、导出报表、PushPlus 提醒 |

## 五、一图看懂每天主流程

```text
【老板 Web】导入手机号 → 配 h5_rush + 活动 ID → 看仪表盘
       ↓
【业务员 App】本机发码/登录客户号（4G）→ 通知老板已登数量
       ↓
【19:50】直购试跑（4G）
       ↓
【20:00】「等到 20 点 · 本机直购」→ 自动抢购 + 补货波次
       ↓
【成交】客户在官方 i茅台 App 付款
       ↓
【老板 Web】预约记录 / 仪表盘统计直购成交数

【可选】9:00 预约 → 18:03 同步中签
```

## 六、官方场次对照（避免搞混）

| 场次 | 时间 | 本软件 | 业务权重 |
|------|------|--------|----------|
| **平价飞天直购**（客户说的「抢酒」） | **20:00** 起 | ✅ 等到 20 点 · 本机直购 | **主 KPI** |
| 申购抽签 | 约 9:00–10:00 | ✅ 等到 9 点 · 本机预约 | 可选 |
| 小茅好运专场 | 每月 29 日 20:05 | 服务器定时 | 可选 |
| 周末欢乐购 | 周日 15:05 | 服务器定时 | 可选 |

**没有 21:00 场次。** 晚上抢茅台指的是 **20:00 直购**。

## 七、服务器自动跑的任务（不用手点）

| 时间 | 任务 |
|------|------|
| 07:00 | Token 失效检查 |
| 07:30 | 低分账号养护 |
| 08:50 | 协议版本巡检 |
| 18:03 | 中签同步 + 待付款提醒 |
| 一三五 08:30 | 小茅运旅行（开启后） |

**模式 B 下**：20 点直购、9 点预约都以 **App 本机操作** 为主，不靠服务器 IP 去抢。老板在 Web 查看结果即可。

## 八、每天检查清单（精简版）

### 业务员

- [ ] Wi-Fi 登录管理 App
- [ ] 负责号全部 **已登录**，并告知老板
- [ ] **19:50 前** 直购试跑通过
- [ ] **20:00** 等到 20 点 · 本机直购（4G，等跑完）
- [ ] 成交号通知客户官方 App 付款

### 老板 / 管理员（Web）

- [ ] 当日 **活动 ID** 已更新
- [ ] 仪表盘看登录数、直购成功记录（主 KPI）
- [ ] 业务员 App 版本 ≥ **1.8.3**
- [ ] 预约记录核对成交与失败原因
